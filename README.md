# Medicare Quality Measure Engine

## What this is

All data in this repository is synthetic, generated by `generate_data.py` in
this repo -- no real members, pharmacies, or diagnoses exist anywhere in it.
This is a SQL engine, built on DuckDB, that computes two medication-
adherence quality measures against that data: Part D Medication Adherence
for Diabetes Medications, and the HEDIS SPD (Statin Therapy for Patients
With Diabetes) measure, both rates.

## Why these measures matter

Part D medication adherence measures are triple-weighted in CMS Star
Ratings, a major lever on a Medicare Advantage plan's score. SPD is an
NCQA HEDIS measure assessing whether diabetic members at elevated
cardiovascular risk stay on statin therapy.

## The interesting problem

Both measures depend on PDC (Proportion of Days Covered), and its trickiest
edge case is the early refill. Naively summing every fill's days_supply
double-counts overlapping coverage and can push PDC above 100%, which is
nonsensical. The fix shifts each early fill's coverage window to start the
day after the prior supply ends, so surplus days push forward instead of
stacking on top of existing coverage.

## Results

From a fresh run of `python build.py` against 500 synthetic members:

| measure | denominator | numerator | rate |
|---|---|---|---|
| Part D Diabetes Medication Adherence | 260 | 154 | 0.5923 |
| SPD Rate 1 (Received Statin Therapy) | 106 | 52 | 0.4906 |
| SPD Rate 2 (Statin Adherence 80%) | 52 | 26 | 0.5000 |

## Verification

Nine hand-constructed members with known expected outcomes (clean fills,
an early refill, a mid-year gap, a death mid-period, late enrollment, a
drug-class switch, ASCVD/hospice exclusions) are included in every
generated dataset and checked against query output on each build.
Two of them, the early-refill and gap cases, are further verified against
independent spreadsheet-style arithmetic in `docs/hand_verification.md`;
the results match.

## Not implemented

- Measure 1 skips the ESRD and certain insulin-only exclusions the real PQA
  spec includes.
- SPD skips ESRD, cirrhosis, myalgia/myopathy/rhabdomyolysis, pregnancy,
  IVF, palliative care, and advanced-illness-with-frailty exclusions.
- `condition_group` is a simplified stand-in for real diagnosis codes;
  `drug_reference` is a small illustrative list, not a licensed NCQA
  HEDIS value set (not reproduced here).
- SPD's hospice exclusion window is read from ambiguous spec wording as "on
  or before 2025-12-31" -- see the comment in `sql/04_measure_spd.sql`.
